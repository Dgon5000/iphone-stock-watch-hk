# iPhone Stock Watch — Apple Store Hong Kong

Присылает уведомление в **Telegram**, когда iPhone 18 Pro Max появляется для **самовывоза (Pick up) в любом Apple Store Гонконга**.

## Как идут проверки

Проверка идёт **каждые 30 секунд вдвоём**: сервер (VPS) смотрит наличие в :00 каждой минуты, GitHub Actions — в :30 и сразу передаёт ответ на сервер.

```
10:00:00  VPS     проверка
10:00:30  GitHub  проверка → по SSH на сервер
10:01:00  VPS     проверка
10:01:30  GitHub  проверка → по SSH на сервер
…
```

Что прислать в Telegram, решает **только сервер**: у него одно состояние на двоих, поэтому каждое изменение приходит **один раз**, а в журнал попадают проверки обоих. Каждый из двух обращается к Apple раз в минуту — столько же, сколько человек, который время от времени обновляет страницу. Если Apple всё же откажет (HTTP 403 или 429), этот компьютер сам сделает паузу на 2, 4, 8, потом 15 минут, а не будет настаивать.

Уведомление приходит при **любом изменении**: конфигурация появилась в наличии (хотя бы в одном магазине) или закончилась (её больше нет ни в одном). Пока ничего не меняется, бот молчит. Пример:

```
🍏 Apple Store Hong Kong

🟢 Появились · iPhone 18 Pro Max
🩶 512GB · Silver — 🛒 Оформить

🩶 1TB · Silver — 🛒 Оформить

🔴 Закончились · iPhone 18 Pro Max
🖤 2TB · Black
❤️ 2TB · Burgundy

🕐 Проверено: 02.10.2026 14:05 (HKT)
```

«🛒 Оформить» — ссылка прямо на эту конфигурацию на apple.com/hk; магазин для самовывоза выбирается при оформлении. Значок перед памятью показывает цвет: 🩶 Silver, 🖤 Black, 🩵 Glacier, ❤️ Burgundy. Варианты с разной памятью разделены пустой строкой, внизу — время проверки по Гонконгу (по часам Apple, поэтому оно точное, даже если часы компьютера отстают).

Пока Apple выкладывает партию, его ответы несколько минут «мигают»: есть → нет → есть. Поэтому «закончилась» бот сообщает, только если конфигурации нет и в следующей проверке, через 30 секунд. Если она вернулась, это было «мигание», и сообщения не будет. О появлении бот пишет сразу.

Каждые **10 минут** (10:00, 10:10, …) бот присылает **без звука** сводку: что сейчас в наличии (со ссылками), чего нет — одной строкой, и сколько было проверок у каждого:

```
🕐 Проверено: 03.10.2026 18:10 (HKT)
🔁 Проверок за 10 мин: 20 — VPS 10, GitHub 10
```

Так видно, что работают оба. Если в момент сводки пришло изменение, сводка придёт со следующей проверкой. Прислать сводку сразу: /iphone в боте или с Mac — `ssh root@IP "bash ~/iPhone_Checker/vps_install.sh status"` (здесь и ниже `IP` — адрес вашего сервера).

### Если один из двух перестал проверять

- **GitHub** перестал присылать проверки (GitHub отключил запуски, сбой) — через 30 минут бот один раз напишет «⚠️ GitHub: проверки не приходят уже 30 мин. Наличие продолжает проверять VPS.» Сервер продолжит проверять раз в минуту. Когда GitHub вернётся — «✅ GitHub: проверки снова работают».
- **Сервер** перестал получать ответы Apple (например, Apple закрыл доступ его адресу) — так же: «⚠️ VPS: проверки не работают…» с последней ошибкой, а GitHub продолжит проверять.
- **Сервер выключен** — уведомления о наличии не приходят (решает только сервер). Через 30 минут об этом напишет GitHub: «⚠️ GitHub не может передать проверки на сервер…».
- **Не работает ни один** — «⚠️ Проверка наличия в Apple Store Hong Kong не работает уже 30 мин».

Короткие сбои не сообщаются.

### Журнал наличия и отчёт

Каждая проверка записывается в `/opt/iphone-stock-watch-hk/stock_history.jsonl` на сервере: время по Гонконгу, кто проверял (`vps` или `github`) и какие конфигурации в каких магазинах были в наличии. Проще всего посмотреть отчёт командой **/report** в боте: он пришлёт, когда что появлялось, сколько держалось, в какие часы и в каких магазинах чаще, и файл-таблицу со всеми появлениями. То же самое с сервера:

```bash
ssh root@IP "bash ~/iPhone_Checker/vps_install.sh report"
```

С таблицей для Excel/Numbers (`;`-разделённый CSV, каждое появление — строка) и копированием на Mac:

```bash
ssh root@IP "bash ~/iPhone_Checker/vps_install.sh report --csv /root/stock_intervals.csv" && scp root@IP:/root/stock_intervals.csv ~/iPhone_Checker/
```

Отсутствие короче 5 минут отчёт считает «миганием» Apple и не делит появление на два. Журнал начинается с 2 октября 2026: утро восстановлено по истории GitHub, дальше — по логу сервера. При проверке каждые 30 секунд журнал растёт примерно на 1 МБ в сутки.

### Команда /iphone

Отправьте боту **/iphone** (команда есть в меню бота, кнопка «/») — он сразу проверит Apple и пришлёт ту же сводку: что в наличии и чего нет. На расписание проверок и на уведомления об изменениях это не влияет: команду обрабатывает отдельная служба `iphone-stock-watch-hk-bot`. Бот отвечает только чатам из `TELEGRAM_CHAT_ID`; повторные /iphone в течение 20 секунд получают тот же ответ без нового запроса к Apple. Лог: `journalctl -u iphone-stock-watch-hk-bot -f`.

Пока бот работает на сервере, `telegram_setup.py` не сможет прочитать сообщения боту (Telegram отдаёт их только одному читателю): при повторной настройке остановите бота командой `systemctl stop iphone-stock-watch-hk-bot`, а потом запустите снова (`start`).

## 1. Создайте Telegram-бота

1. В Telegram откройте **@BotFather**, отправьте `/newbot`, придумайте имя и username (должен заканчиваться на `bot`). BotFather пришлёт токен вида `123456789:AAH…`.
2. Откройте своего бота по ссылке от BotFather и нажмите **Start** — без этого бот не сможет вам писать.
3. Узнайте chat ID:

   ```bash
   python3 telegram_setup.py
   ```

   Скрипт спросит токен, найдёт ваш чат и пришлёт в него подтверждение. Символы при вводе не отображаются: вставьте токен один раз (`Cmd + V`) и сразу нажмите Enter. Нужен только Python 3, сторонние библиотеки не нужны.

   Без скрипта: откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":123456789`.

Чтобы уведомления приходили в группу, добавьте туда бота, напишите в группе любое сообщение и снова запустите `telegram_setup.py` — у группы chat ID отрицательный. Несколько получателей — через запятую.

Токен бота — это пароль: не коммитьте его в репозиторий.

## 2. Запустите сервер

Сначала сервер (см. «Запуск на VPS» ниже): он главный и работает и без GitHub — тогда проверка раз в минуту.

## 3. Подключите GitHub

### Репозиторий

Рекомендуется **публичный** репозиторий: в публичных репозиториях стандартные GitHub Actions бесплатны и без лимита минут. Токены и ключи в файлы не кладите — только в секреты (ниже).

Создайте на github.com пустой репозиторий (без README и .gitignore) и загрузите в него все файлы этой папки, включая `.github/workflows/`:

```bash
cd ~/iPhone_Checker
git init -b main
git add .
git commit -m "Apple Store Hong Kong stock watch"
git remote add origin https://github.com/<ваш-логин>/<имя-репозитория>.git
git push -u origin main
```

Или через сайт: **Add file → Upload files** и перетащите содержимое папки. Скрытую папку `.github` Finder перетащить не даст, поэтому перед загрузкой переименуйте её в `github` (скрытые файлы показывает `Cmd + Shift + .`). После загрузки создайте на GitHub файлы с правильным путём: **Add file → Create new file**, имя наберите на клавиатуре — `.github/workflows/stock-watch.yml`, вставьте содержимое одноимённого файла из `github/workflows/` (на его странице есть кнопка **Copy raw file**) и нажмите **Commit changes**; то же для `test-telegram.yml` и `watchdog.yml`. Без папки `.github/workflows` с точкой ничего запускаться не будет.

### Ключ, которым GitHub передаёт проверки

GitHub входит на сервер как пользователь `stockfeed` по отдельному SSH-ключу. Этот ключ умеет **только одно** — передать проверку: сервер запускает для него лишь приём проверок (`check_stock.py --ingest`), без командной строки и пересылки портов. Даже если ключ утечёт, с ним нельзя ни войти на сервер, ни прочитать токен бота. Всё — на Mac, в Терминале:

```bash
ssh-keygen -t ed25519 -N '' -C github-feed -f /tmp/feed_key
```

```bash
ssh root@IP "bash ~/iPhone_Checker/vps_install.sh feed-key '$(cat /tmp/feed_key.pub)'"
```

### Секреты GitHub Actions

В репозитории: **Settings → Secrets and variables → Actions → Secrets → New repository secret**, или командами (`gh` — GitHub CLI):

- `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather (нужен GitHub, только чтобы предупредить, если сервер недоступен)
- `TELEGRAM_CHAT_ID` — ваш chat ID из шага 1 (несколько — через запятую)
- `FEED_SSH_KEY` — закрытый ключ: `gh secret set FEED_SSH_KEY < /tmp/feed_key`
- `FEED_HOST` — адрес сервера: `gh secret set FEED_HOST --body IP`
- `FEED_KNOWN_HOSTS` — ключ самого сервера, чтобы GitHub не подключился к чужому: `ssh-keyscan -t ed25519 IP | gh secret set FEED_KNOWN_HOSTS`

Потом удалите ключ с Mac: `rm /tmp/feed_key /tmp/feed_key.pub` — он остаётся только в секретах GitHub.

### Проверьте

1. **Actions → Test Telegram Alert → Run workflow.** В Telegram придёт тестовое сообщение с текущим наличием всех 12 конфигураций.
2. **Actions → iPhone Stock Watch (Apple Store Hong Kong) → Run workflow.** В логе шага «Check Apple at :30…» раз в минуту появляются строки вида:

   ```
   [2026-10-03 18:00:30 HKT] 6 stores × 12 models checked — no pickup stock
   ```

   а в логе сервера (`journalctl -u iphone-stock-watch-hk -f`) — те же проверки с пометкой `GitHub:`.

Запуск остаётся «в работе» почти 6 часов, потом сам запускает следующий — так и задумано. Нажать **Run workflow** нужно один раз; если цепочка прервётся, «Сторож» (Stock Watch Watchdog) перезапустит её в течение часа.

GitHub сам пишет на почту об упавших запусках. Если эти письма не нужны, на github.com/settings/notifications в разделе **System → Actions** снимите **Email**: о сбоях и так сообщит Telegram.

## Если проверка сломалась

Если проверки не проходят дольше 30 минут подряд (Apple блокирует запросы, изменил API или в `PART_NUMBERS` неверный артикул), бот один раз пришлёт предупреждение (см. «Если один из двух перестал проверять»). Когда всё восстановится, придёт «✅ … снова работает». Короткие сбои не сообщаются.

Если не приходит даже тестовое сообщение, ошибка видна в логе Test Telegram Alert:

| Ошибка | Что сделать |
|---|---|
| `HTTP 401 Unauthorized` | Неверный или отозванный `TELEGRAM_BOT_TOKEN` |
| `HTTP 404 Not Found` или `TELEGRAM_BOT_TOKEN is malformed` | Токен вставлен с лишними или недостающими символами — скопируйте его заново |
| `Bad Request: chat not found` | Неверный `TELEGRAM_CHAT_ID` |
| `Forbidden: bot can't initiate conversation with a user` | Откройте бота и нажмите Start |

Если GitHub не может передать проверки, в логе запуска видна причина: `Permission denied (publickey)` — ключ на сервере не тот (снова `feed-key`), `Host key verification failed` — неверный `FEED_KNOWN_HOSTS`, `check not taken: the watcher … has not read checks` — служба проверки на сервере остановлена.

## Другие модели

Свой список артикулов через запятую, например `MJXU4ZA/A,MJXT4ZA/A`, задаётся **в двух местах одинаково**: на сервере — строкой `PART_NUMBERS=…` в `/opt/iphone-stock-watch-hk/config.env` (потом `systemctl restart iphone-stock-watch-hk`), на GitHub — переменной `PART_NUMBERS` в **Settings → Secrets and variables → Actions → Variables**. Если списки разные, проверки GitHub идут только в журнал. Apple отдаёт не больше 20 артикулов за запрос; если указать больше, скрипт сам разобьёт их на несколько запросов.

## Как остановить

- **Только GitHub** — сервер продолжит один, раз в минуту: **Actions → iPhone Stock Watch (Apple Store Hong Kong) → … (справа вверху) → Disable workflow**, затем откройте текущий запуск и нажмите **Cancel workflow run**. Через 30 минут бот один раз напишет «⚠️ GitHub: проверки не приходят» — так и должно быть. «Сторож» отключённую проверку не запускает. Включить обратно — **Enable workflow** и **Run workflow**.
- **Всё**, когда iPhone куплен: на сервере `ssh root@IP "bash ~/iPhone_Checker/vps_install.sh uninstall"` (службы удаляются, доступ GitHub по SSH закрывается) и GitHub, как выше.

## Как бот помнит, что уже сообщал

`stock_state.json` на сервере хранит, какие конфигурации были в наличии при последней проверке, кто проверяет и о чьём сбое уже сообщено. Сообщение приходит, только когда список наличия меняется. Если отправить сообщение не удалось, список не обновляется, и сообщение повторится со следующей проверкой. GitHub своего состояния не хранит — он только передаёт проверки.

## Запуск на VPS

Самый надёжный вариант, работает круглосуточно: любой Linux-сервер с systemd (Ubuntu 22.04/24.04, Debian 12), подойдёт самый дешёвый тариф. С Mac скопируйте папку на сервер и запустите установщик:

```bash
scp -r ~/iPhone_Checker root@IP:~/
```

```bash
ssh -t root@IP "bash ~/iPhone_Checker/vps_install.sh"
```

Установщик спросит токен бота (ввод скрыт) и chat ID, пришлёт тестовое сообщение и запустит две службы: проверку (в :00 каждой минуты, сводка раз в 10 минут, плюс проверки от GitHub) и бота с командами /iphone и /report. Обе сами запускаются после перезагрузки сервера или сбоя. Если вы входите не под `root`, запускайте через `sudo bash …`.

Другое расписание: `EVERY=60 OFFSET=0 STATUS_MINUTES=10 bash ~/iPhone_Checker/vps_install.sh` — проверка каждые `EVERY` секунд со сдвигом `OFFSET` секунд от начала минуты, сводка раз в `STATUS_MINUTES` минут (`0` — без сводок). GitHub проверяет в :30 (задано в `.github/workflows/stock-watch.yml`), поэтому сдвиг сервера оставьте 0.

Лог: `journalctl -u iphone-stock-watch-hk -f`. Обновить скрипт: снова скопируйте папку и запустите установщик — настройки, ключ GitHub и память бота сохранятся. Удалить: `sudo bash ~/iPhone_Checker/vps_install.sh uninstall`.

Apple может блокировать адреса некоторых хостингов. Тогда через 30 минут бот пришлёт «⚠️ VPS: проверки не работают…», а проверять продолжит GitHub.

## Запуск на своём Mac

Вместо сервера проверку можно запускать на Mac — с паузами 1, 2, 3 минуты по очереди и сводкой раз в 10 минут, в том числе после перезагрузки и входа в систему. Но только пока Mac не спит, и без GitHub: проверки GitHub умеет принимать только сервер.

1. Сохраните настройки Telegram на этом Mac — на вопрос «Сохранить токен и chat ID…» нажмите Enter:

   ```bash
   python3 telegram_setup.py
   ```

   Они сохранятся в `~/.config/iphone-stock-watch-hk/config.env` — вне папки проекта, чтобы токен случайно не попал на GitHub.

2. Включите проверку — в Telegram придёт тестовое сообщение:

   ```bash
   bash macos.sh install
   ```

macOS может показать уведомление о новом фоновом объекте `python3` — это и есть проверка. Другие команды: `bash macos.sh status` (работает ли и последние проверки), `bash macos.sh log` (лог в реальном времени), `bash macos.sh uninstall` (выключить). Другие паузы, например 5, 3 и 4 минуты по очереди: `bash macos.sh install 5,3,4`.

Разовая проверка без отправки сообщений: `python3 check_stock.py --dry-run`.

## Кто главный

Сообщения отправляет одна копия — та, что ведёт состояние: сервер (вместе с GitHub, который только передаёт ему проверки) **или** Mac. Если запустить проверку и на сервере, и на Mac, у каждой будет своя память, и сообщения будут приходить дважды.

## Чем отличается от оригинала

- Уведомления в Telegram вместо почты, плюс сообщения о сбоях проверки.
- apple.com/hk вместо apple.com/uk и артикулы `…ZA/A`. Почтовых индексов в Гонконге нет: на запрос с районом `Central` Apple возвращает все 6 магазинов.
- 12 конфигураций одним запросом вместо одной; название модели берётся из ответа Apple.
- Проверка каждые 30 секунд: сервер и GitHub по очереди, с одним состоянием на двоих. Расписание «каждые 5 минут» GitHub на практике запускает раз в 15–20 минут (это видно по истории коммитов оригинала).
- Исправлена проверка `storeSelectionEnabled`: в ответе Apple это поле лежит в `messageTypes.regular`, а оригинал искал его уровнем выше и фактически смотрел только на `pickupDisplay`.
- Неверный артикул (например, британский) — явная ошибка, а не тихое «нет в наличии».

## Ограничения

- API самовывоза Apple недокументирован и может измениться. Скрипт делает только публичные read-only запросы, как страница магазина, и не обходит CAPTCHA, авторизацию, ограничения частоты или защиту от ботов: каждый компьютер спрашивает раз в минуту, а при отказе Apple делает паузу.
- GitHub разрешает Actions для задач самого проекта; круглосуточная проверка — серая зона, и GitHub может отключить запуски. Тогда сервер продолжит один, раз в минуту, а бот предупредит.
- Проверка постоянно занимает один сервер GitHub Actions. Для публичного репозитория это бесплатно, но это постоянная нагрузка — после покупки остановите проверку (см. «Как остановить»).
- Если у GitHub сбой и цепочка запусков прервётся, «Сторож» перезапустит её в течение часа; его собственное расписание GitHub тоже может немного задерживать.
- В публичном репозитории GitHub отключает расписание «Сторожа» после 60 дней без активности. Включить снова: **Actions → Stock Watch Watchdog → Enable workflow**.
- Наличие меняется быстро. Перед поездкой проверьте магазин и время выдачи на сайте Apple.
